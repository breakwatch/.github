### The problem

Vendors ship breaking changes with little or no warning. Changelogs go unread. Deprecations slip by. Production breaks — and your team finds out from error logs, not release notes.

### What we build

- **Codebase-aware dependency mapping** — we don't just watch endpoints, we know which files in *your* repos actually use them.
- **Continuous vendor monitoring** — changelogs, OpenAPI specs, and SDK releases tracked across 16+ vendors, including the AI APIs that move fastest.
- **Context-rich alerts** — Slack and email alerts that name the exact affected files and what to do about it, not just "something changed."
- **A public radar** — every classified change, browsable at [breakwatch.ai/radar](https://breakwatch.ai/radar).

### How it works

```
install → map dependencies → watch vendors → classify changes → alert affected files
```

Read-only GitHub access. Your code is never stored. Per-installation isolation — your data is never mixed, compared, or shared across accounts. Never used to train AI models.
